## 🧠 About This Journey

I am undertaking this **100+ Days of Machine Learning** challenge to build deep, first-principles intuition and practical engineering skills across the machine learning spectrum.

Rather than skimming through high-level tutorials or treating machine learning models as black boxes, this repository serves as my open laboratory to:
- Understand the mathematical foundations and geometric intuition behind every algorithm.
- Write clean, idiomatic Python code for data preprocessing, modeling, and validation.
- Work with messy, real-world datasets and extract actionable insights through rigorous EDA.
- Experiment with hyperparameter behavior, loss curves, and evaluation trade-offs.
- Build reproducible machine learning pipelines and end-to-end projects.

Every day represents deliberate practice: exploring concepts, coding implementations, documenting takeaways, and learning from debugging edge cases.

---

## 🎯 Goals

- [x] **Build Strong Foundations** — Master statistical learning theory, optimization techniques, and core ML taxonomy.
- [ ] **Develop Mathematical Intuition** — Understand linear algebra, calculus, and probability concepts powering ML algorithms.
- [ ] **Master Data Preprocessing & Feature Engineering** — Handle missing data, outliers, encodings, transformations, and feature selection effectively.
- [ ] **Perform In-Depth EDA** — Uncover patterns, distributions, anomalies, and correlations with visualization tools.
- [ ] **Implement Core Algorithms** — Understand and code regression, classification, clustering, and ensemble methods.
- [ ] **Rigorous Evaluation & Validation** — Master cross-validation, metric selection, bias-variance trade-offs, and diagnostic tools.
- [ ] **Build End-to-End Projects** — Assemble standalone experiments into structured, reproducible ML pipelines.
- [ ] **Cultivate Daily Engineering Discipline** — Maintain clean code, structured documentation, and an active learning log.

## 📝 What Each Day Documents

To ensure genuine depth and retention, each day's documentation covers six essential pillars:

1. **Concept & Theory** — What the concept is, its real-world purpose, and where it fits in the ML workflow.
2. **Intuition & Geometry** — How the algorithm behaves geometrically and why it makes specific decisions.
3. **Mathematical Formulation** — Key equations, cost functions, loss surfaces, and optimization routines.
4. **Code Implementation** — Hands-on Python implementation using Scikit-Learn or built from scratch.
5. **Experiments & Observations** — Testing hyperparameter variations, edge cases, and behavior on diverse datasets.
6. **Key Takeaways & Debugging Lessons** — Important insights, mistakes made, assumptions challenged, and debugging takeaways.

## 💡 Learning Principles

- **Understand Before Memorizing** — Understand why an algorithm behaves the way it does, its mathematical assumptions, and its failure modes before relying on standard library syntax.
- **Implement, Don't Just Watch** — Active coding and building intuition through experimentation beats passive consumption.
- **Experiment with Data** — Shift parameters, introduce noisy features, distort distributions, and observe how model behavior changes.
- **Document with Rigor** — Writing concise, clear documentation solidifies understanding and creates a permanent technical reference.
- **Progress Over Perfection** — Consistent daily progress and continuous iteration compound into strong long-term engineering depth.

---

## 🎯 The "100+ Days" Philosophy

This challenge is about **depth of understanding**, not an artificial race against time.

- A "Day" represents a unit of focused, meaningful progress.
- Complex concepts (such as Regularization, Gradient Boosting, or Dimensionality Reduction) may span multiple days of intense study and experimentation.
- The `+` signifies that learning is continuous: this repository will remain an active, evolving reference well beyond Day 100 as I explore production ML, Deep Learning, and real-world system design.
